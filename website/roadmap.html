暂停与试验

  • GitHub Actions 云端 HAP 打包仍暂停；当前 CI 做领域/公开安全检查和静态官网部署，不提供正式 HAP。
  • 网络中转已实现 TDLib/WSS 本地适配与多线路管理，Cloudflare 无系统 VPN 真机文字/媒体已有独立证据；继续验证更多服务、弱网、长时恢复与不同网络。公开文档不提供私人部署入口。
  • 通话、Stories 和其他 Web A 能力依矩阵继续推进；本页分组不是缩减完整目标。

通知与离线推送：Worker 中转方案（待实施）

2026-10-30 用户确认先记录为后续工作，本轮不开发或部署。优先验证 Cloudflare Workers 承担中转，无需预先租用常驻服务器；这是候选方案，尚未取得端到端联调证据。

目标链路：Telegram Simple Push → Cloudflare Worker → HarmonyOS Push Kit → 手机通知。

  • 华为侧准备：为 Harlgram 关联正确的应用包名、开通 Push Kit，并核实聊天通知分类、后台消息等权益与准入条件。服务账号密钥只放 Worker Secrets，不进入 Git、客户端或日志。
  • Telegram 触发：通过项目固定 TDLib 的 registerDevice / deviceTokenSimplePush 注册 Worker HTTPS 接收地址；验证 Telegram 实际请求格式、重注册和注销行为。Simple Push 只提供更新信号，不提供消息正文，不能按完整消息推送实现或宣传。
  • 第一阶段呈现：优先验证通用「你有新消息」通知，点击后由手机连接 Telegram 同步。后台自动拉取、发送者/正文预览与精确会话跳转另行验证，不从收到一次 HTTP 回调推断这些能力可用。
  • 隐私边界：Worker 不登录 Telegram，不持有用户账号会话或数据库，不拉取或保存聊天正文；仅保存路由所需的最小映射，例如随机接收端点与华为 Push Token。接收端点按敏感凭据保护，支持失效与撤销，日志不得记录完整端点、Token 或密钥。
  • 可靠性与滥用防护：处理重复信号、限流、华为接口失败与重试、Token 更新/失效及退出登录后的解绑。不能依赖 Worker 内存或无限后台执行保证投递；需要持久化或队列时再选择最小必要能力。
  • 真机验收：分别验证前台、后台、锁屏、进程被系统回收及网络恢复；核对通知权限、静音、去重和点击后的同步行为。记录后台权益限制与无法覆盖的场景，不能承诺所有退出/强制停止状态都能唤醒。

实施前复查官方依据：Telegram Simple Push、华为 Push Kit 接入流程、Workers HTTP 请求 与 Secrets。华为开通、Telegram 回调、Worker 中转和真机通知均需独立取得证据，当前全部待实施/验证。

当前集成的关键检查

  1. 模式切换后旧 TDLib 更新不会污染离线演示数据，离线恢复不会被重新播种覆盖。
  2. 历史分页与实时入站同时发生时不丢消息；发送回执正确替换临时 ID。
  3. 会话排序保留 int64 精度，未读、置顶、静音与服务端更新一致。
  4. Asset 读取失败不重新生成数据库密钥；关闭后重启可恢复同一数据库。
  5. 开发者自有 API 配置通过本机文件注入；私有源文件和生成文件均未被 Git 追踪；正式 release guard 已验证拒绝缺失或无效配置。
  6. 未发生账号认证和双向消息验证前，项目描述保持为「真实接入开发中」。

近期交付边界

当前工作以已创建的鸿蒙基础工程为起点，建立可持续迭代的原生客户端和真实 Telegram 链路。界面复刻、源码架构参考、底层协议接入和完整 Telegram 功能覆盖是不同的工作项；项目状态应逐项反映进展。

Roadmap

Updated: 2026-10-31. The goal is feature-by-feature Telegram Web A mobile parity with native ArkUI interactions. Single-column phones and the folded wide-fold device come first. No unverified release dates or claims of full parity.

Features describes current scope; the changelog records changes. The detailed Web A matrix defines acceptance. 中文.

Foundation delivered

Real authentication, two-account switching, core message actions, rich display, mixed albums, progressive native video, per-account storage management, three-state appearance, source publication and the website exist with separate evidence. Their remaining boundaries are on the Features page, rather than labeling them wholly absent.

Paused and experimental

  • Cloud HAP builds in GitHub Actions remain paused. CI checks domain/public safety and deploys only the static site; no official HAP is published.
  • The TDLib/WSS bridge and multiple-route manager are implemented, with independent Cloudflare messaging/media evidence on a device without VPN. Other services, weak networks and connection-limit recovery need separate acceptance. Private deployment addresses remain unpublished.
  • Calls, Stories and other Web A capabilities remain in the full matrix; these groups do not narrow that scope.

Notification candidate

Telegram Simple Push may trigger a Worker that forwards a generic notification through HarmonyOS Push Kit. Huawei entitlement/token routing, registration/revocation, retry and actual background delivery still need implementation/verification. The Worker must not hold Telegram login sessions or message bodies; tapping should sync on the device. This is a roadmap design, not an operational push service.
