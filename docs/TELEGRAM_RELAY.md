# Telegram 网络中转试验

2026-10-31 用户最初要求配置 EdgeOne 和 Cloudflare，随后明确本轮先以 Cloudflare 完成。试验服务与其他服务隔离。

## 协议与端侧边界

候选协议 `harlgram-tunnel-v1` 使用 WSS：`/v1/tunnel?host=<Telegram IPv4>&port=443`，通过 `Authorization: Bearer <部署独立随机令牌>` 鉴权。WebSocket 只传二进制帧，按顺序拼接为透明 TCP 字节流；不传 TDLib JSON、不在服务端运行 Telegram 账号会话。TLS 必选，继续保留端侧 MTProto 加密。

目标仅允许 Telegram 官方公布的 IPv4 网段，端口限 80、443、5222；拒绝任意域名、私网、重复参数和在 URL 中携带访问令牌。网段依据 <https://core.telegram.org/resources/cidr.txt>，当前尚无自动更新、IPv6 或 UDP 通话支持。

试验限制：单帧最多 256 KiB、待写入最多 1 MiB、单连接累计最多 128 MiB。Cloudflare 连接 10 分钟关闭，EdgeOne 110 秒关闭以适应平台执行时长；端侧连接恢复交由 TDLib 处理，长时恢复仍待验收，禁止失败后静默直连。大媒体、背压、弱网和长时间连接仍需专项验收。

服务地址是自定义 WSS 通道。应用内「设置 → 网络和代理管理」添加配置并填写域名、访问令牌与请求头；RelayTunnel 在 127.0.0.1 随机端口提供带随机认证的 SOCKS5，只供本应用 TDLib 使用，再转换为 WSS。所有目标校验与证书验证保持开启，队列上限 1 MiB，单次发送切成 64 KiB；不支持域名目标、IPv6 或 UDP。Telegram MTProto 与 WSS TLS 均保留，不新增自制加密。

配置由 RelayPreferences 写入独立 Asset 项；输入只接受域名或 HTTPS/WSS origin，不接受路径、查询或 URL 内令牌。启用前先验证随机 nonce，成功才关闭旧连接、保存并重连。TDLib 启动先排队 networkTypeNone 与 addProxy，收到 addedProxy 才放行 networkTypeOther；缓存的 Ready 不能绕过代理确认。选择直接连接会保留全部配置并显式 disableProxy。错误保持可见，禁止自动直连。切账号或进程重启重新建立本机监听和凭据，数据库密钥不变。

## 名称与用户配置说明

对外简称「中转代理」，技术名称为「WebSocket 隧道代理」（此实现将 TCP 字节流封装到 WSS）。应用明确选择并连接中转，不采用「透明代理」作为功能名称；「透明传输」只描述不改写 MTProto 字节流，不代表网络层自动拦截。HTTP 反向代理可以是部署链路中的一环，但普通网页反代不具备本协议要求的 TCP 转发能力。WebSocket 协议依据 [RFC 6455](https://www.rfc-editor.org/rfc/rfc6455.html)。

应用管理页和编辑页右上角均提供官方 HDS 帮助图标入口，进入原生分组列表的「配置说明」视图，页面返回和系统返回均先关闭说明并保留原编辑输入；查看说明不保存或切换线路。内容以简短介绍、三步使用和四个字段组织；默认/自定义 Header 的发送例子、自行部署前提与作用范围放在可展开的「更多说明」中。

用户需从可信服务提供者取得兼容 `harlgram-tunnel-v1` 的域名、32～256 字符令牌和请求头名称；示例域名 `relay.example.com`。域名可以带 HTTPS origin，但不能有路径、查询或令牌。名称自定，令牌只填原始内容，不附加 Bearer；请求头默认 Authorization，自定义值必须与服务端一致。不要填写 Telegram 登录凭据或机器人令牌，也不能将现成 SOCKS5 / MTProxy 地址当作本通道地址。

流程为「添加 → 测试连接 → 保存配置 → 使用此配置」；测试不保存，新建配置不自动选中，非活动项编辑不重连。自行部署需要有效 HTTPS 证书、WebSocket 双向传输、Telegram TCP 转发及独立令牌校验；仅配置 DNS 或反代网页不够。此说明不承诺某个托管平台部署成功即线路可用，必须通过实际 Telegram 握手。只影响本应用，不设置系统 VPN 或其他应用代理，UDP 通话不在支持范围。

## 网络和代理管理

「设置 → 网络和代理管理」保存最多 32 条命名中转配置；每项分别保存域名、访问令牌和令牌请求头，可添加、编辑、测试、选择、重新连接及删除。空选择代表显式直接连接，切换直连不会删除已有配置。当前项须先切换到另一项或直连后才能删除，删除用系统确认弹层；编辑页返回不隐式保存。

Asset 中使用版本化 v2 registry。旧版单条配置会在读取时保留域名、令牌及启用选择迁移为一条记录，首次成功保存才覆写；无法读取或活动 ID 丢失不会静默改为直连。保存非活动项不打断现有连接；切换或修改活动项先做 Telegram nonce 测试，失败保留原选择。Asset 写入失败尝试恢复原连接；若新监听启动失败，页面读取真实已保存状态并显示错误，不伪装旧连接仍然生效。

令牌请求头默认为 `Authorization`，发送 `Authorization: Bearer <token>`；大小写等价的 authorization 归一为该默认字段。其他自定义头（例如 `X-Relay-Token`）直接发送 `<token>`，不添加 Bearer。服务端必须显式配置同样的字段及匹配方式，客户端不能自行改变已有服务器的鉴权规则。字段名仅允许以英文字母开头、后续字母/数字/下划线/短横线，最长 64 字符；拒绝 Host、Connection、Upgrade、Cookie、Sec-*、Proxy-*、Content-* 等协议或系统保留字段及 CR/LF，令牌不进入 URL。

当前自有 Cloudflare 部署仍使用默认 Authorization；EdgeOne 独立部署配置自定义请求头，HTTP 鉴权已验证，完整 WSS 端到端仍受下述断流阻塞。私人域名、令牌和平台临时预览签名不随源码公开。
