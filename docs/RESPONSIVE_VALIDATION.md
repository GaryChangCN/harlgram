## 设计验收矩阵

下表为需要满足的标准，文档建立不等于源码已经满足。宽高均指应用内容容器的可用 `vp`，不是设备物理屏幕像素；示例宽度用于构造测试，不是某个型号的实测尺寸。

| ID | 场景 | 建议窗口条件 | 设计验收标准 |
| --- | --- | --- | --- |
| D01 | 手机竖屏 | 320 / 360 / 480 vp 宽 | 单栏；会话行、返回和输入完整；短消息气泡不拉伸。 |
| D02 | 手机横屏 | 实际宽度跨入 medium 或 expanded，低可用高度 | 按窗口宽度布局；低高度仍可输入、返回和滚动，不按「手机」固定单栏。 |
| D03 | 平板竖屏 / 横屏 | 600 / 720 / 1024 vp 宽 | medium 过渡布局可操作；expanded 必须主从双栏；登录与设置内容不无限拉宽。 |
| D04 | 大屏窗口 | 1280 vp 或更宽 | 会话栏与消息内容宽度有界；空详情栏简洁；交互目标保持合理大小。 |
| D05 | 折叠设备收拢 → 展开 → 收拢 | 跨 compact / medium / expanded | 当前会话、草稿、筛选和可见消息锚点保留；无重复发送或重新登录。 |
| D06 | 阔折叠横竖切换 | 按每次实际宽高，而非设备标签 | 长宽比变化后仍按同一规则；避免折痕/不可交互区域；不挤压输入栏。 |
| D07 | 分屏 / 自由窗口连续缩放 | 599 → 600、839 → 840 vp 及反向 | 断点切换无抖动；以应用当前容器宽度判断；不沿用整屏尺寸。 |
| D08 | 键盘与系统安全区 | 单栏及双栏，键盘出现/隐藏 | 输入可见、发送可操作；不重复扣安全区、不遮挡底部手势区。 |
| D09 | 跨断点状态连续性 | 已输入草稿、滚到历史中部、保留搜索词 | 布局变动后文本和位置保留；不强制滚至最新消息、不重置列表。 |
| D10 | 大字号与长内容 | 系统字体放大、长昵称、长 URL | 无关键按钮遮挡；文本合理换行/省略；错误和发送状态仍可识别。 |
| D11 | 核心 Telegram 行为 | 所有布局 | 返回恢复来源；可见聊天阅读状态正确；发送失败文本保留。 |
| D12 | 简洁与原生实现 | 所有页面 | 官方 ArkUI；无 Android UI/WebView 替代、宣传口号、重复 label 或日常开发技术说明。 |
