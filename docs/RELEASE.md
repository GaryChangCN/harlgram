# 发布源码与开发预览

本文是后续发布操作说明，不表示已有稳定二进制、应用商店版本或已完成的发布认证。公开源码、部署介绍网站、分发签名 HAP 是三件独立的事，分别确认范围与结果。

## 公开源码

1. 确定发布 commit，并同步中英文 README、`STATUS.md` 和功能矩阵。逐项区分已实现、已编译、已运行和已获服务端验证，不以测试数量代替功能覆盖。
2. 运行领域/配置测试，审阅 Git 索引与准备公开的历史，确认签名、API、本地目录、数据库、二进制与真实截图均不在其中。`check-public-tree.py` 与 `--staged` 模式均检查完整 Git index 快照，包括 index 中的公开图片清单；不能代替历史与图片的人工审查。
3. 核对 `LICENSE`、`THIRD_PARTY_NOTICES.md`、[许可说明](LICENSING.md)、随包许可和实际依赖版本。上游参考源码、实际复制代码、随包二进制与构建工具分别记录；新增素材需要可追溯来源。
4. 从干净 checkout 按 README 验证初始化和构建路径。保留测试与构建结果，公开摘要只包含版本、命令、结果和限制，不发布含本机路径或账号信息的原始日志。

仅文档/网站变化不要求重做账号操作。涉及 SDK 或协议的改动需要相应编译和行为证据，缺失项如实记录。

## 分发 HAP 前

- 使用发布者自己的 Telegram API 身份和正确签名，执行 `./scripts/build.sh release`。配置 guard 检查格式和已知禁用值，不能证明配置归属或已满足所有平台要求。
- 对照当前 [Telegram API 条款](https://core.telegram.org/api/terms) 和 [第三方声明](../THIRD_PARTY_NOTICES.md) 审查客户端行为、品牌标识与依赖义务。当前功能矩阵仍有缺口，不能仅凭 release 构建成功宣布可正式面向终端用户分发。
- 确认目标 ABI 的 OHOS TDLib、Node-API 桥及运行库实际进入 HAP；记录 SDK、TDLib commit、OpenSSL 版本和源码补丁。Android 库不能替代 OHOS 库。
- 使用隔离的首次安装环境以及获授权的升级环境分别验证启动与配置行为。升级保持 bundle、签名和数据兼容；不在真实账号实例卸载主应用或同 bundle 测试包。
- 依据本次变更验收登录、发送失败/恢复、草稿、权限、媒体与生命周期。真实消息动作只使用明确授权的测试会话和合成内容；用户本人完成登录。
- 检查应用内第三方许可、对应源码和构建材料的可获取性。分发二进制时，按适用许可提供匹配版本的对应源码与必要说明，不能只给一个会不断变化的分支链接。

HAP、签名私钥和应用数据库不是同类产物：分发经审查的安装包不意味着应公开签名凭据、账号材料或构建者的本地配置。源码仓库继续忽略 Native 库、HAP 和私有文件。

## 发布记录应包含

| 项目 | 内容 |
| --- | --- |
| 身份 | 版本 / tag、对应 commit、发布日期；实验版本明确标记为预览。 |
| 能力 | 本次实际改变的用户行为，已知缺口和未验证路径。 |
| 环境 | SDK 与 ABI、已测 OS/API 和设备形态；不含设备序列号。 |
| 安装与升级 | 签名/安装条件、与既有版本的兼容性；有迁移风险时先说明。 |
| 证据 | 领域测试、SDK 编译、设备验收、服务端同步分别记录。 |
| 产物 | 仅在实际提供文件时列出文件名、SHA-256 和对应源码入口；没有二进制就明确为源码发布。 |
| 许可与安全 | 许可/依赖声明入口及 `SECURITY.md` 私下报告渠道。 |

截图只展示虚构或去敏内容。合成机身框需说明是示意，不能用单张画面证明完整折叠、旋转或多窗口行为。项目网站介绍与 README 保持相同能力边界；上线前没有实际文件的下载按钮、未执行 CI 的成功徽章和未验证设备支持声明应移除。

## 静态官网

源码目录为 `website/`，无构建依赖；本地预览：

```bash
python3 -m http.server 4173 --directory website
```

工作流 `.github/workflows/pages.yml` 只上传该目录，通过官方 Pages Actions 部署。仓库 Pages 配置使用 GitHub Actions，项目已启用 HTTPS。官网使用默认 Pages 地址 `https://garychangcn.github.io/harlgram/`，不使用自定义域名。更换账号或 fork 后，应修改网站 canonical / Open Graph 和 README 入口为自己的 Pages 地址，并自行启用 Pages；不要保留他人的域名配置。

网站默认中文，可切换英文；不引入追踪、外部字体或第三方脚本。配图的隐私审查、元数据清理和校验值流程见 [PUBLIC_ASSETS.md](PUBLIC_ASSETS.md)。首次源码发布保持一个 `init` 根提交，Pages 部署不另建 `gh-pages` 提交历史。
