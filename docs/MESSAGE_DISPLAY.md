# 消息展示与 Web 手机尺寸对照

更新：2026-10-31。消息内容和结构以用户指定的同一授权账户、Telegram Web A 手机尺寸为准；导航、菜单和交互仍使用原生 ArkUI。当前不是全部消息类型或所有版式全面对齐。

## 本轮发现与修复

对照 Web 的 460 CSS px 手机视口和指定真机未展开形态。三个群聊分别覆盖多人短句/回复、长文本/富内容、照片/相册；不在公开文档记录群名称、成员名称、账号标识或消息正文。第三组已对照到同段照片与相册，正文片段经去除时间/表情图片差异后有匹配；实时活跃群的画面并非每一屏都处于完全相同时间点。

| 发现 | 当前实现与证据边界 |
| --- | --- |
| 富内容整条显示「暂不支持」 | 实测诊断到 `messageRichMessage`，按固定 TDLib schema 解析 RichText/PageBlock；常见段落、标题、列表、引用、代码、链接、分隔线及嵌入照片/视频进入原生渲染；真机真实富文本已显示，不只修整普通 Text 的样式 |
| 富文本属性被丢弃 | 保留 UTF-16 entity offset，原生 Span 合并粗体、斜体、下划线、删除线、等宽、链接和剧透；引用/代码使用独立区块。链接仅用户点击才打开，拒绝危险 scheme；未实际打开群内外链 |
| 头像缺失、每条重复发送者 | 按发送者/方向/会话/时间/日期/转发来源分组；连续发言减少间隔和重复姓名，在组尾显示头像。真实群成员头像与连续短句已真机复核 |
| 回复只有通用「回复消息」 | 当前聊天中限并发请求 `getRepliedMessage` 补原文与发送者，不插入旧消息改变历史顺序；可用时显示受限大小缩略图。原消息不可用明确呈现，剧透在摘要中保持隐藏 |
| 转发、系统消息都像普通文字 | 转发显示来源；常见入群/退群、头像/群名变更和置顶等系统消息居中呈现。匿名/未知来源不伪造身份 |
| 气泡高、时间固定占一行 | 减少内边距，正文 15fp、元信息 11fp；时间/编辑/发送状态随最后一行自然换行，无说明媒体使用角落叠加；已读双勾只依据服务器 outbox read 更新，未把发送成功当已读 |
| 图片统一裁成固定高度 | 单项按服务器宽高计算，限制最高 420vp；媒体最大宽 400vp。相册按比例排布，三项首图横图时上大下双图，首图竖图时左大右双图，消除旧两列奇数空格 |
| 联系人、表情、贴纸内容丢失 | 联系人卡显示姓名和号码；animated emoji 保留可读表情，静态贴纸/动态贴纸缩略图预览。GIF/animation 可走媒体预览；语音时长、文件名和投票内容有只读呈现，不把它们写为播放/下载/投票均已实现 |
| 最后消息被输入区遮挡 | 媒体/回复补齐引起内容高度变化时，在布局之后跟随底部；只以用户滚动决定退出跟随，翻历史时不强拉回底部。滚动和原历史分页锚点仍需继续验收复杂竞态 |

对 `richMessage.is_full === false` 提供「展开全文」，通过 `getFullRichMessage` 加载原消息的完整版本；去重、错误重试和 30 秒超时已实现，过期响应不覆盖当前状态。未在真机专门构造长文截断/超时故障，因此不写为真实服务端故障验收通过。

## 代码入口

- `model/MessagePresentation.ts`：安全链接、实体切分、块拆分、剧透摘要、连续发言及媒体几何。
- `telegram/RichMessage.ts`：固定 schema 的递归富文本/富内容解析，限制递归深度与区块数，不执行 HTML。
- `components/MessageText.ets`：原生 Text/Span、引用/代码、用户主动揭示剧透和打开链接。
- `TelegramClient.ts` / `TdTypes.ts`：保留内容、发送者、转发、链接预览和服务器已读语义；读取回复、完整富消息和受控媒体下载。
- `ChatRepository.ts`：归并普通消息与富内容嵌入媒体的缓存路径/进度。
- `Index.ets`：消息分组、头像、气泡、相册、引用与滚动状态。

上游依据：本地固定 TDLib `td_api.tl` 的 `formattedText`、`RichText`、`PageBlock`、`messageRichMessage`、`getFullRichMessage`、`messageReplyToMessage`；Web A 固定源码的 `MessageRichText`、`RichContent`、`calculateAlbumLayout`，结合已登录页面的实际测量。新几何实现为本项目的有限规则，不宣称覆盖 Web 所有相册优化布局。

## 验收与接力

领域测试覆盖 UTF-16/emoji、嵌套样式、危险链接、剧透、引用/代码、2–10 项布局边界、跨发送者/日期分组、富内容解析/嵌入媒体归属、全文加载/失败/过期响应和服务器已读。SDK 26 编译签名、真机覆盖安装与启动分别执行。最终 280 项通过；SDK 26 编译签名、指定真机覆盖安装/启动通过。底部跟随和历史键盘往返已复核，6 个可见消息锚点位置保持，原收藏夹草稿逐字一致。实际接力见 [STATUS.md](STATUS.md)。

原始截图和布局只在 ignored artifacts，主要文件：`message-web-group-{1,2,3}-*-private.png`、`message-native-group-{1,2,3}-*-private.png`、`message-ui-tests.log`、`message-ui-build.log`、`message-ui-install.log`。它们含真实群内容，禁止作为 README/官网配图直接公开。

尚未完整对齐：所有相册比例组合、复杂表格与折叠区块、数学排版、富内容按钮、定制 emoji/贴纸完整动画、反应/置顶条、完整链接预览图片、语音/文件/投票的完整交互。未用原生完整实现的能力不以静态预览冒充完成。其他设备、展开、横屏和分屏本轮不扩展。

SDK 26 本机组合曾出现透明尾 Span 令前文不绘制的画面，已改为不换行空白预留和独立元信息叠加；最终真机说明文字与右侧时间均可见。这是该组合的实测规避，不宣称为所有 SDK 的全局缺陷。
