# 路线图

更新：2026-10-31。目标是逐项对齐 Telegram Web A 手机尺寸的真实能力，交互采用鸿蒙官方 ArkUI。先做好手机单栏和阔折叠未展开窗口，再扩展其他形态。不承诺未验证的发布日期，不把已有源码或截图当作全面通过。

[现有功能](FEATURES.md) 记录完成范围，[更新日志](../CHANGELOG.md) 记录变化；[Web A 矩阵](TELEGRAM_WEB_PARITY.md) 是逐项验收依据。English: [ROADMAP.en.md](ROADMAP.en.md)。

## 已交付的基础

真实登录、双账户切换、基础消息操作、富内容展示、图片/视频相册、原生流式播放器、当前账户存储管理、三态外观和公开源码/官网已实现，并有各自测试证据。详细边界统一放在现有功能页，不在待办中重复列为「完全缺失」。

## 优先级与验收条件

| 优先级 | 下一步 | 完成条件 |
| --- | --- | --- |
| P0 · 当前链路正确性 | 历史跨页引用/锚点、完整已读、发送与草稿并发、更多权限/失败恢复 | 真实跨端复核；切聊天/键盘/网络变化不丢草稿、不重复发送，不伪造送达 |
| P0 · 媒体与缓存可靠性 | 更多编码/容器、非 faststart、弱网/断网/音频中断；上传暂存安全回收 | 合成材料真机覆盖；缺片可恢复、关闭不留任务；回收有引用索引，不能删除待发送/重试素材 |
| P1 · 查找与组织 | 服务端全局/聊天内搜索、归档、云端文件夹、资料和共享媒体 | 结果来自真实服务端，分页/过滤/权限准确，返回保持来源和位置 |
| P1 · 完整消息能力 | 任意文件、语音/音乐、贴纸/GIF、消息多选/反应/置顶与完整引用 | Web A 对应入口、TDLib 请求、原生交互及真实收发分别验收 |
| P1 · 多账户完整性 | 非活动账户同步/通知、更多未读/草稿/文件/退出隔离 | 退出或清理一个账户不影响另一个，旧更新不能污染当前账户 |
| P2 · 设置与管理 | 隐私/设备会话、群/频道管理、权限、邀请与成员；更多下载例外 | 服务端权限驱动入口和结果；敏感/不可逆操作有明确范围与确认 |
| P2 · 系统通知 | 系统通知权限、后台送达与点击同步 | 华为权益/Token、注册/注销、重试、后台真机送达和点击同步通过，默认不传消息正文 |
| P2 · 播放器增强 | 画中画、字幕/多音轨、质量切换、自动保存相册 | 平台/消息确实提供能力后再实现；权限和生命周期独立验收 |
| P3 · 更多形态与可用性 | 展开/收拢、旋转、平板、大屏、分屏、多窗口、大字号/无障碍/更多语言 | 当前账户、会话、草稿、搜索和滚动锚点连续，不重复请求或发送 |
| 发行门槛 | 可分发构建、源码/许可/依赖材料、签名、版本与包验证 | 可重建且无私密材料泄露；发布配置检查和许可通知通过，二进制与源码对应 |

## 暂停与试验

- GitHub Actions 云端 HAP 打包仍暂停；当前 CI 做领域/公开安全检查和静态官网部署，不提供正式 HAP。
- 通话、Stories 和其他 Web A 能力依矩阵继续推进；本页分组不是缩减完整目标。

## 当前集成的关键检查

1. 模式切换后旧 TDLib 更新不会污染离线演示数据，离线恢复不会被重新播种覆盖。
2. 历史分页与实时入站同时发生时不丢消息；发送回执正确替换临时 ID。
3. 会话排序保留 int64 精度，未读、置顶、静音与服务端更新一致。
4. Asset 读取失败不重新生成数据库密钥；关闭后重启可恢复同一数据库。
5. 开发者自有 API 配置通过本机文件注入；私有源文件和生成文件均未被 Git 追踪；正式 release guard 已验证拒绝缺失或无效配置。
6. 未发生账号认证和双向消息验证前，项目描述保持为「真实接入开发中」。

## 近期交付边界

当前工作以已创建的鸿蒙基础工程为起点，建立可持续迭代的原生客户端和真实 Telegram 链路。界面复刻、源码架构参考、底层协议接入和完整 Telegram 功能覆盖是不同的工作项；项目状态应逐项反映进展。

## 通知与离线推送（待实施）

通知权限、后台送达、点击后同步及退出解绑仍需实现和独立真机验证，当前不承诺离线通知可用。
