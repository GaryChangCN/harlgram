# 存储管理

入口为真实账户的「设置 → 数据与存储 → 存储管理」。能力参考用户提供的 Nicegram 数据/存储页面；功能验收仍遵循 Web A 范围，页面使用 SDK 26 原生 ArkUI。没有引入 Nicegram 代码或素材。

## 已实现

- TDLib `getStorageStatistics` 分类占用与原生 DataPanel 圆环：图片、视频/视频消息、动图、贴纸、头像、文件、音频/语音、其他缓存。未知、秘密及安全文件单列为不可选择的受保护文件。
- 勾选类型后清理全部或指定会话的本地缓存；列出占用最大的 12 个会话。确认后调用 `optimizeStorage`，按实际删除统计报告释放空间。不会请求删除云端消息、注销账号或删除数据库。
- 私聊/群组/频道分别设置永久、1 天、1 周、1 个月或 3 个月保留；媒体缓存上限不限、1/2/5/10 GB。默认永久且无上限，修改期限会立即尝试整理。
- Wi-Fi、移动网络、漫游分别设置图片/视频/动图开关与单文件上限。默认 Wi-Fi/移动网络仅自动下载图片，漫游关闭；未知网络和未知大小保守不自动下载。手动下载独立，头像和必要缩略图仍有固定小额限制。
- NetworkKit 观察实际网络变化、TelephonyKit 读取漫游状态，不保存 SSID、运营商、IP。VPN 优先使用系统非计费标识，否则按蜂窝/漫游状态保守处理；无法判断不套用宽松配置。
- TDLib 累计网络发送/接收用量按网络类型显示；数据库、日志、上传暂存只读显示。设备总量/剩余量来自 CoreFileKit。
- 策略只存各账户独立 Preferences；不存在消息/用户信息快照。切换账户后旧请求不能覆盖新状态，失败/断连/30 秒超时均有错误出口。

## 安全与边界

所有删除都经 TDLib，不扫描或删除加密数据库、安全凭据和账号目录。删除请求必须有非空的已知媒体类型白名单，不能将空数组传成 TDLib 的默认广泛类型集合；所有限制显式填写，不用 `-1` 意外启用默认 TTL/大小/文件数清理。完成后重新读取已知文件状态，清除失效显示路径。

当前打开的会话及待发送/失败发送媒体所在会话整体排除。自动清理只包括照片、视频、动图、文件、音频，不自动清理公共头像、贴纸和未知归属文件。自动期限按 TDLib 上次访问时间计算，保留至少一小时免清理窗口。TDLib 可因文件仍被使用而少于预计释放，界面显示实际值。

清理只针对当前连接账户。自动维护在应用进程运行时、进入前台或保存设置后尝试，通常间隔至少 30 分钟；没有宣称杀进程后仍可定时清理。上限约束的是可回收媒体，受保护、正在使用和其他保留文件可能使总占用超过上限。统计会话超过 10000 时剩余归并到 0，不按会话期限清理；界面只列前 12 项。

上传暂存先只读显示并保留。现有上传生命周期尚无完整的持久引用索引，不能凭文件年龄删除用户待发送/重试材料。自动保存相册、流式播放、联系人级下载例外、逐媒体浏览清理、后台清理和完整上传暂存回收仍在路线图中。并非 Nicegram 全设置复制或 Web A 全面对齐。

## 验证

宿主机回归覆盖类型白名单、网络/大小策略、请求关联/超时、TTL 与上限的独立限制、受保护会话、账户隔离、切换竞态和文件状态刷新。ArkTS 需另跑真实 SDK 编译，不以转译测试替代。

2026-10-31 指定阔折叠真机未展开形态已读取真实分类用量，勾选视频、取消确认、对收藏夹执行选择性清理，实际报告释放 816 KB；没有发送/删除云端消息。已验证清理后合成视频重开并播放到结尾、既有草稿保持；由于自己发送的素材保留上传暂存，此次播放不能单独作为云端重下载证据，后者仍待专项验证。图片自动下载开关及大小偏好冷启动保留。292 项宿主测试、真实 SDK 编译、覆盖安装和启动通过，完整证据与未验证场景见 STATUS.md。原始截图含会话名时仅留在忽略目录，不作公开配图。

协议依据：项目固定 `td_api.tl` 的 getStorageStatistics、getStorageStatisticsFast、optimizeStorage、getNetworkStatistics 和 setNetworkType；[官方 optimizeStorage 文档](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1optimize_storage.html)。
