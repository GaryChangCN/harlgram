# 现有功能

更新：2026-10-31。Harlgram 是开发中的 HarmonyOS NEXT 原生 Telegram 第三方客户端，尚未全面对齐 Telegram Web A。本页说明实际能力与边界；[路线图](ROADMAP.md) 说明后续计划，[更新日志](../CHANGELOG.md) 记录变化，[逐项 Web A 对齐矩阵](TELEGRAM_WEB_PARITY.md) 提供更细的功能入口与验收条件。

## 如何理解状态

「已实现」是有真实协议与原生交互；「真机验证」只覆盖列出的动作和设备；「部分」表示仍有明确缺口。宿主测试、SDK 编译、设备启动与真实服务端同步分别记录，不能互相替代。当前主要验收手机单栏与阔折叠真机未展开窗口，不由单一场景推断所有编码、账户或设备均通过。

## 功能与验证范围

| 领域 | 当前能力 | 已有验证 | 边界 / Web A 差距 |
| --- | --- | --- | --- |
| 登录 | 国家/区号与手机号分离，验证码、已有两步密码、邮箱认证；注册状态、重发、30 秒超时与错误出口 | 两个真实账户登录、覆盖安装和正常重启保持 | 注册、所有收码渠道和异常恢复并未逐一真实验收 |
| 多账户 | 二级账户管理、头像、添加/切换；各账户凭据、加密数据库与下载策略隔离；未完成登录不列入账户 | 两个账户往返、冷启动恢复及头像保持 | 仅活动账户连接；非活动账户实时通知、完整退出/草稿/未读隔离仍待更多验收 |
| 会话与联系人 | 真实列表、头像、未读、草稿摘要、历史分页，已有联系人与收藏夹；置顶/静音入口 | 真实列表与会话打开、历史、草稿、头像 | 搜索/筛选仅已加载数据；没有服务端全局搜索、云端文件夹和完整归档 |
| 文本与消息操作 | 收发与发送状态、回复、编辑、转发、按权限删除、复制入口 | 文本收发，回复/编辑、转发到收藏夹、仅为自己删除在真机和 Web 同账号核对 | 复制入口未单独实机执行；跨页引用定位、完整已读语义、多选/反应及复杂权限待补 |
| 消息展示 | 原生富文本、常见 RichMessage 区块、群发送者/头像、连续发言、日期、转发与回复摘要 | 三组真实群聊只读对照；合成媒体/草稿回归 | 复杂区块、完整贴纸/GIF 与其他特殊消息不能算全面支持 |
| 图片与相册 | 系统最多 10 项图片/视频混选、说明、移除、分组发送，网格、前后浏览、图片缩放及确认后保存 | 双向照片/视频相册与独立视频，系统保存、双击缩放 | 原文件、质量/编辑/重排、HEIF、连续双指手势和更多失败场景待完善 |
| 视频播放 | AVPlayer 边下边播、未缓存定位后自动恢复、前后 30 秒、七档倍速、长按临时 2×并松手恢复；单击/双击/横滑、控制栏、静音、后台暂停 | 150 秒 H.264/AAC MP4 真机冷缓存起播、远端定位、跨片段至结尾、1.5×→2×→1.5×与 30 秒跳转通过 | 更多编码、非 faststart、真实弱网/来电、画中画、字幕/音轨及清晰度切换未完成 |
| 存储与网络 | 当前账户分类占用、类型/会话清缓存、私聊/群/频道期限、缓存上限；按 Wi-Fi/移动/漫游设置图片/视频/动图自动下载与大小；网络用量 | 真实统计、选择性清理、清后视频重取、偏好跨冷启动保持 | 自动维护仅进程运行时；非活动账户、上传暂存安全回收、联系人级例外、自动保存相册待补 |
| 原生外观 | 官方 ArkUI、系统菜单/弹层、玻璃底栏、浅色/深色/跟随系统及安全区 | 真机外观保存、系统跟随、覆盖安装/重启保持 | 完整无障碍、大字号与所有系统变化场景仍需专门验收 |
| 折叠与大屏 | 按可用宽度设计，已有展开双栏静态画面 | 已有脱敏真机静态展示 | 完整折叠/旋转/分屏状态连续性尚未验收，当前优先未展开形态 |
| 离线预览 | 与真实账户隔离的虚构本地数据 | 领域测试与 UI 开发入口 | 本地操作不代表云端送达 |

## 明确尚未支持

- 服务端全局/聊天内搜索、真实云端文件夹、完整归档与资料/共享媒体。
- 任意文件、语音/音乐完整收发，完整贴纸/GIF 交互、消息多选/反应、群/频道管理。
- 后台推送与可靠离线通知、语音视频通话、Stories、完整隐私/设备会话管理。
- 画中画、字幕/多音轨、质量切换及全部设备形态验收。

网络中转与通知方案仍在试验/路线图阶段；服务端实验不等于应用已具备对应能力。不要依赖当前开发预览接收重要通知。
